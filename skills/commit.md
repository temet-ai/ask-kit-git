Make a commit: what to stage, how to word the message, what to leave out

1. Read `await git.status()`. If an operation is in progress (`operation` is not null), stop and
   report it; a commit in the middle of a rebase or merge is a different job (see `conflicts`).
2. Decide what belongs. Stage only the paths the request names or that plainly belong to the change
   it describes. Other changed files may be another session's work in the same checkout: leave
   them, and list them in the answer as "not staged".
3. Leave out anything that looks like a secret or a local file: `.env*`, `*.pem`, `*.key`,
   `id_rsa*`, `credentials*`, `*.sqlite`, editor and OS files. Say that you left it out.
4. Read the diff of what you will stage: `await git.diff({ path: [...], patch: true })`. The message
   describes that diff, not the request.
5. Match the repository's style. `await git.log({ max: 10 })` shows whether subjects are
   `type(scope): summary`, a plain sentence, or prefixed with a ticket. Follow what is there.
   - Subject: what changed, in the imperative, 72 characters at most, no full stop.
   - Body, when the diff needs one: why, and what a reader of the code cannot see. Wrap at 72.
   - No attribution, co-author or "generated by" lines unless the last ten commits carry them.
6. Stage and commit with exact paths:
   `await git.run("add", "--", ...paths)` then
   `await git.run("commit", "-m", subject, "-m", body)`.
   An editor never opens here, so every commit needs `-m` (or `--no-edit` for an amend).
7. If a hook rejects the commit, report the hook's output as it is. Do not pass `--no-verify`
   unless the request asks for it.
8. Answer with the new short sha, the subject, the files committed and the files left unstaged.

Amending: only the last commit, and only when `git.contains("HEAD")` shows no remote branch holds
it, or the request says to amend a pushed commit. Otherwise make a new commit.

Pushing: `git.run("push")`; a first push of a branch is `git.run("push", "-u", "origin", branch)`.
A rejected push means the remote moved: fetch, report what is new there, and stop unless the
request said to rebase or merge.
